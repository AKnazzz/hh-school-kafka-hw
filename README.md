По факту трогать надо KafkaProducer и TopicListener

Нужно чтобы каждый листенер работали по своей семантике - at most once, at least once, exactly once - это и проверяет тест

========================================================================

## Изменения и их Объяснение

### KafkaProducer:
Обработка сообщений происходит повторно до тех пор, пока они не будут успешно отправлены. Это решает проблему с семантиками **at least once** и **exactly once**, когда сообщения могли прерываться из-за исключений.

### Service:
Аналогичным образом, обработка сообщений повторяется до тех пор, пока они не будут успешно обработаны. Это предотвращает потерю сообщений из-за случайных ошибок в методе `handle`.

### TopicListener:
- Для **at most once** добавлена логика игнорирования исключений, чтобы обеспечить как минимум одну попытку обработки.
- Для **at least once** введены повторные попытки отправки сообщений.
- Для **exactly once** добавлено множество обработанных сообщений для предотвращения повторной обработки.
